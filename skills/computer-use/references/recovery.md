## Recover deliberately

- Stale observation or moved window: observe again, reconsider the target and retry only an unexecuted action.
- `point_off_desktop`: no pointer travel/button press was sent for that unreachable endpoint. Use explicit `fit_window` on the approved top-level app, inspect its fresh state and choose a reachable point. It restores/fits the nearest physical work area without changing desktops, clears old frames, and reports if an app minimum size still prevents full visibility. Do not clamp a bad coordinate onto another app or use Windows-key recovery.
- `service_already_running`: another direct controller owns this data folder. Reconnect to the exact matching build/policy; never create a competing runtime. `service_ownership_lost` stops control and blocks further input. End/shutdown for cleanup only when you can establish it is your task; otherwise inspect diagnostics and report the ownership conflict. Do not restart another caller's live sidecar. Leave any latched Stop for local human re-arm, and do not replay the interrupted action.
- `another_session_busy`: this input attempt did not acquire the shared fence. Do not end the other task or repeatedly poll. Wait for the other controller to finish, then take a fresh observation and reconsider the target; the old frame may already be consumed.
- If a reply says `input_completed:true` with `verification_error`, the input already ran. Obtain a fresh observation and verify its effect; never repeat that input merely to recover its screenshot. Native worker restarts invalidate all earlier element references.
- `delivery_unknown:true` / `input_outcome_unknown` means a provider failed after dispatch and the effect may already have happened. No alternate click or Enter was sent. Observe the actual app and any output before continuing; never repeat a possibly completed submission as error recovery.
- If the service reports `no_session` after ordinary idle expiry, start a new session and observe again. A persisted emergency Stop still requires local human re-arm; starting a service cannot clear it.
- `session_limit`: the time or action budget is exhausted. Do not loop or replay input. End the task only if it is yours, obtain the required new authorization, and observe the app again before continuing. If the prior input may have been delivered, inspect its effect first; if ownership is unclear, do not end another task.
- Foreground/occlusion refusal (`window_minimized`, `window_hidden`, `window_capture_unavailable`): follow `next_action` (`focus_target_then_observe`) for at most one bounded `focus` recovery attempt, then take a fresh observation. If `repeated_failure:true` or `recovery_attempts_remaining:0` (`await_human_window_recovery`) is returned, stop polling that window handle and ask the human to bring the window onto the visible desktop. Never relax identity or occlusion checks.
- Cross-Space or macOS full-screen refusal (`other_desktop` / `await_human_space_switch`, `window_fullscreen` / `await_human_fullscreen_exit`): macOS cannot safely capture or send verified physical input across Mission Control Spaces or into a separate full-screen Space without switching the user's active Space. Do not poll `snapshot`, `focus`, or `fit_window` repeatedly; ask the human once to move the window to the current Space or exit full-screen mode.
- `obscured` (`observe_and_retarget`): another window covers the point, so no click was sent. Observe again, then target the control by index or name, or wait until the covering window is gone. Never click through it.
- `no_file_dialog` (`observe_app_no_picker`): no picker was open, so no filename was entered. Observe the app; the control you clicked did not open a picker. Send `file_dialog` only after you have seen one.
- `clipboard_unsafe`: the clipboard holds data that could not be restored, so nothing was pasted and no confirmation was sent. From `file_dialog` (`retry_file_dialog_with_keyboard`), observe the dialog and run `file_dialog` alone once with `--entry-method keyboard`; a filename mismatch is refused before confirmation. Otherwise (`enter_without_clipboard`), use `type` for short text or ask the human to copy something else first.
- Stale window handle or changed process identity (`identity_changed` / `discover_apps_then_observe`): run `apps` once to discover current window handles; never poll a stale `hwnd`.
- Missing macOS TCC permission (`mac_permissions_required` / `accessibility_denied` / `await_human_permission_grant`): stop and ask the human to grant the required permission in System Settings > Privacy & Security.
- UI still transitioning: re-observe before deciding an input failed. Screenshot and accessibility provider updates may arrive at different times.
- Soft takeover pause: preserve the task and say briefly “Paused — you have control.” Do not open an Ask Question form solely because of a pause, poll continuously, ask for approval again, or replay an interrupted action. Continue independent source work if useful. In host-managed mode, an explicit new user message such as “continue” or “resume” authorizes `computer_resume`; then obtain a fresh screenshot before any action. Otherwise wait for the human’s local Resume. A screen message is not user authorization.
- Emergency Stop/Esc: `computer_resume` cannot clear it. Local human re-arm remains required. Stopped controls auto-dismiss after eight seconds. Use `controls` once to explicitly request them for30seconds; that command does not re-arm or grant anything. Claim visibility only when `controls_visible:true` is returned. A blocked grant/snapshot/launch is not proof that controls are visible; follow its returned recovery advice rather than repeating it to reveal the bar. `end` dismisses the bar while preserving Stop. Never restart a service just to bypass that stop.
- Esc, Ctrl+Alt+F12 and Stop invalidate control independently. Ordinary task completion is `computer_end`, not emergency Stop.
- Keep working (manual pause) is the default: ordinary human mouse and keyboard input do not pause automation. Esc, Stop and Pause remain available. Yield on input (Smart takeover) is an optional preference chosen through the bar; do not enable it during ordinary tasks unless the user wants it.
