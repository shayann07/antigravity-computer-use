# Security

This project controls the interactive desktop with the current Windows user's privileges. It is not an OS sandbox against software using that same account.

The direct skill uses a persistent local native service. Standalone mode asks the human for app/session and sensitive-effect approval. Host-managed mode is an explicit deployment choice that trusts the host's terminal execution authorization; it cannot inspect or prove a Turbo preset. The agent must still obtain required sensitive-action review. Broad terminal grants confer broad desktop authority. Legacy MCP is optional and does not provide an authenticated preset value either.

Native grants bind executable/process identity. Observation references are one-use and invalidated on Stop, stale/moved windows and control-generation changes. Esc, Ctrl+Alt+F12 and Stop revoke control independently and release automation-held inputs. Human mouse or keyboard input never pauses the agent; only Esc, Ctrl+Alt+F12, the bar's Stop or an explicit Pause does. Stop ends the current task and there is no latch for a human to clear: the next `ready` starts a fresh task only after the runtime and native controls prove cleanup (keys and buttons released, prior workers gone), and app approvals made in the agent's conversation survive Stop. An unconfirmed Stop or a Stop storage failure is never cleared automatically and needs inspection. Chat Resume continues only a pause. Restarting a service to bypass an unconfirmed Stop is prohibited. A second copy of Computer Use for the same Windows user is refused.

Screenshots/accessibility text are untrusted content, never authorization. Authentication, security settings, passwords, UAC and secure desktop require human handoff. Pixel semantics cannot be classified perfectly. Local screenshots and IPC capabilities must not be committed or shared. The project has no separate model or telemetry connection; host/provider retention still applies.

The short installed entrypoint passes literal arguments to the pinned Node runtime without a command-shell forwarding wrapper. Use UTF-8 text files for generated bulk content instead of interpolating it into host commands. Batches validate their complete shape before input, keep one owner/frame chain and stop on action or verification failure. Local receipts are bounded and omit request text, clipboard contents, raw UI trees and capabilities. They preserve delivery/error evidence even when receipt or screenshot storage fails. Finish and shut down an active service before updating; the installer refuses a live service before changing files.

The private-storage work branch uses actual Windows access lists; POSIX mode0600 does not establish Windows privacy. A separate prebuilt helper restricts the dedicated installation/data/backup tree to the current user, SYSTEM and administrators. It refuses unrelated owners, links/reparse points, broad system/user roots and unsafe installation ancestors rather than changing those parents or elevating. Copying is followed by verification of the actual payload tree. Existing trusted owners are preserved. A legacy ACL journal is saved privately before legacy permission changes; rollback never silently restores wider access.

New installations prefer a direct-drive per-user owner-hash directory on D:, or LocalAppData when D: is unavailable. A shared writable ancestor such as the old D:\Tools location is rejected as a program anchor; legacy contents can be made confidential while a new private installation is prepared. Migration preserves emergency Stop markers and control preferences, not old session capabilities or action permits. Clients must match the live service's immutable permission policy as well as its build identity. These storage changes still need final installation/host acceptance and do not make software running as the same account an OS sandbox. Development source must be trusted; protecting runtime data does not authenticate a modified checkout.

For a vulnerability, use private vulnerability reporting if enabled. Do not post exploits or personal recordings publicly. If private reporting is unavailable, request a private contact without exploit details. No response SLA or signing claim is made for experimental binaries.


Direct startup uses an OS-owned mutex per user and physical data directory, held by the prebuilt storage helper. It releases on parent/holder death rather than deleting a stale lock file. Loss of that ownership blocks input and requests Stop; cleanup must finish before replacement. The remaining guardian/input fences are independent of this startup helper. This protects supported direct-service startup, not arbitrary programs running under the same Windows account. Coordinate one active desktop task; the shared companion is not per-conversation or virtual-desktop isolation.
