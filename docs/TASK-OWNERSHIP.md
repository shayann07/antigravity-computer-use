# Task ownership and cross-installation coordination

The direct Sidecar coordinates cooperating clients using a server-issued bearer capability. The first `ready` CLI call acquires it internally and returns `task_token`. Supply `--task TOKEN` on subsequent task commands, including End. Acquisition uses another local IPC message inside the same CLI process, not another agent/tool decision round trip. An unused reservation expires after 30 seconds; a used reservation never transfers by elapsed time. A lost reply or missing token never permits another caller to adopt an open task. Tokens are excluded from receipts and shareable diagnostics.

This token is not a host-authenticated conversation identity and does not isolate malicious programs running with the same Windows/macOS account and full filesystem access. No model-provided conversation name, PID or working directory authorizes a task. Status, discovery, local controls and emergency Stop remain available independently; other commands are checked before input, grants or task closure. Recovery End is permitted only for a recovered task and still requires the native old-actor/ledger checks.

Updated direct services use one private per-account coordination directory under `~/.gemini/computer-use-control/desktop-task-lease`. The native mutex/flock spans the task lifetime. The same helper publishes `task-owner.json` while holding that lease. Input cannot begin before ownership publication is acknowledged. A helper crash leaves an open record, and another installation refuses takeover while prior cleanup is unverified. End publishes a closed record only after native cleanup and local task closure. A Stop in the previous owning installation blocks subsequent owners until local recovery/re-arm. A failed close publication keeps ownership unresolved and prevents a successful End response.

The service checks the registered global installation and projects listed in its deployment registry for live pre-protocol controllers. Those must be ended and shut down before control begins. Unregistered legacy runtimes and unrelated desktop automation cannot be retroactively forced to honor this protocol; running them concurrently is unsupported. Optional legacy MCP integrations are not covered by the new direct-service admission protocol.

## Evidence and remaining qualification

`tests/task-ownership.test.mjs` exercises two authenticated IPC clients, separate CLI processes, capability expiry, foreign End rejection and token exclusion from receipts. `tests/task-coordinator.test.mjs` exercises the real native lease and journal writer with two inert installation directories, helper death, closed-owner recovery and a synthetic Stop marker. Tests stay inside `.localdata`; the native coordination fixture injects its storage-verification boundary and is not full ancestor-ACL or physical input qualification. Registered legacy refusal is tested without desktop access.

Real concurrent Antigravity conversations, native human Stop/re-arm, shared cursor recovery, actual OS permission prompts and release update/rollback remain hardware acceptance gates. Source tests do not establish those results. The installed published beta.4 runtime has not been replaced by this candidate.

The local control menu includes **End session and hide** for abandoning a lost client. That trusted native event uses the same Stop/End cleanup proof before releasing the task capability and shared lease; it preserves ordinary Stop and cannot manufacture re-arm. Explicitly requested controls remain visible until dismissed or the task changes state, rather than disappearing during a human handoff. A `ready` reply includes a reusable `task_command_prefix`, so agents can append commands without reconstructing the installed paths or task token.
